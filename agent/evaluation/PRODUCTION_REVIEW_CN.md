| 会话隔离与确定性指代 | 最近的计划可能把猜测实体带入下一轮。较早发起的任务迟到后也可能进入正在运行的任务上下文。 | 入口先按会话和运行起点取快照。明确写出的本轮对象优先。只有上一轮有唯一、经核验且类型匹配的对象时才接续指代。多个可能对象进入澄清节点。 |
| 分层记忆和压缩 | 前三轮的问题与较早实体直接进入规划提示词，窗口外的旧结论无法确切回查。 | LangGraph 检查点保存执行状态。最近三轮与较早分析摘要保留在 1,200 字符的序列化窗口。SQLite 保存分析索引和完整历史，可按轮次或主题回查。规划器收到本轮解析后的问题。 |

| 工具失败与程序性记忆 | 临时故障已有重试和检查点。上一轮补查的实际成败无法影响下一轮选取备用工具。 | 同一会话记录可归因的补查成败，只调整既有备用工具的优先级。工具参数、重试预算、工作流确认条件仍由程序控制。 |
| 证据和结果 | 关系路径曾以工具统计和关系编码为主。图谱问答缺少释义时会直接止步。 | 从可核验的边重建路径，输出自然语言、方向和逐条引用。明确登记号可核验对应的 Milvus 资料，登记快照标明来源类型。图谱缺少通用释义时使用 Qwen3 基础模型，登记判断和用药问题要求来源。 |
| 发布前验收 | 早期验收主要检查计划执行，缺少对答案正确性和来源命中的验证。 | 回归同时检查冲突有无误调用、补参后是否使用正确登记号、时间回查结果、跨会话泄漏、路径是否真的连通，以及证据来源是否匹配登记号。 |

## 本地验证

在同一 Agent 会话依次发送 `记住登记号 00A657-62 从 2020-01-01 起`、`更正登记号为 4387-901 从 2025-01-01 起`、`截至 2024-12-31 记住的登记号是什么` 和 `用记住的登记号查登记资料`。前者的历史查询应返回 00A657-62，当前检索应精确使用 4387-901。若同时指定两个登记号而未明确对比或覆盖，预期先澄清，随后继续同一任务。

用 `回顾第1轮`、`回顾「苹果」` 或 `总结本会话` 检查历史。轮次按该会话的已结束分析计算。日期按东八区解释。用 `按 2026-11-22 当时已知，截至 2024-12-31 记住的登记号是什么` 可分别指定两种时间。

Spring 问答的备用路由由 `AGENT_ANSWER_URL` 配置，例如 `http://127.0.0.1:8091/api/agent/answer`。Qwen3 LoRA 负责复杂规划，基础权重负责通用释义。登记快照的来源是恢复后的登记数据，引用指向相应图谱记录。

## 上线前仍需验证

- 账号与会话所有权。SQLite 查询限定会话，本地入口仍需在对外开放前增加登录、所有权校验和存储配额。
- 并发与延迟。模型实例复用 GPU，本地单进程作为运行基线。还需用真实峰值流量检验排队、服务超时和恢复，并建立延迟分位数与工具失败率看板。 [OpenAI Agents SDK Tracing](https://github.com/openai/openai-agents-python/blob/main/docs/tracing.md)
- 来源时效和答案质量。真实登记快照需要持续同步，实际用药以对应地区现行标签为准。通用回答需要领域审核和真实坏例回放，语法及关键词规则覆盖目前已实现的查询和风险类型。
