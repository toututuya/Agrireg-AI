## 优化内容

旧查询对每个搜索词执行多属性 `CONTAINS` 全图扫描，最短路径需要分别扫描起点和终点。新流程为：

1. 对 8 类实体的 `normalized_name` 和有效成分 CAS 建立索引；
2. 先通过索引解析精确节点 ID；
3. 只有精确解析失败时才执行兼容旧行为的模糊包含查询；
4. 最短路径直接按两个已解析节点 ID 查询，仍限制在 6 跳以内；
5. 评测请求可传 `persist=false`，避免污染真实对话历史。

没有通过缓存制造更好看的基准数字，因此结果反映数据库查询与 API 序列化的实际开销。测试为本机顺序请求，不等价于生产并发容量；上线前仍应补充固定硬件、预热轮次、并发梯度和长时间稳定性测试。

## 评测集构成

- 448 条分层实体检索，占当前节点数 2.0634%；
- 52 条直接与两跳最短路径；
- 45 条有证据 GraphRAG 正例；
- 5 条不存在实体负例；
- 固定随机种子 `20260827`，便于同一图谱快照复现。

语义问题会过滤重复词和明显异常机器翻译名称。第一次抽样发现两条异常名称并导致端点约束失败，这一过程说明评测也能反向发现数据清洗问题。异常不会从原始数据记录中删除，而应进入来源核验与修订队列。
