# 项目讲解与面试准备

## 30 秒版本

AgriReg AI 是一个面向农药登记、植保研究和合规人员的全球农药知识图谱。我把农药登记、作物、病虫害、有效成分和作用机制组织成 Neo4j 多层网络，前端用原生 SVG 关系画布做交互探索和最短路径分析；问答侧采用有状态的两阶段 GraphRAG，恢复最近对话以理解追问，再从 Neo4j 取证据，最后限制模型只能依据图谱关系回答并附引用。

## 10–20 分钟讲解结构

### 1. 背景与用户（2 分钟）

传统农药数据分散在登记表、有效成分表、作物和病虫害表中。用户真正想解决的不是“浏览某个地区页面”，而是跨来源回答：

- 某个有效成分出现在哪些登记产品中；
- 某作物有哪些病害与登记防治药剂；
- 两个实体通过哪些登记记录或作用机制产生关联；
- 一个 AI 回答由哪些图谱关系支撑。

因此产品定位是“全球农药知识的关系检索与可追溯问答”。

### 2. 图谱建模（3 分钟）

实体层包括 RegisterNumber、Crop、Disease、ActiveSubstance、ChemicalClasses、PesticideCategory、TargetSite、ModeOfAction。关系包括 TREATS、INFECTS、APPLIED_TO、INCLUDES、REL_TYPE、DETERMINES。

讲解时用一条链路说明：

`作物 ← APPLIED_TO — 登记产品 — INCLUDES → 有效成分 → 化学类别 / 靶点 / 作用方式`

地区不应作为单独产品入口，而应作为登记来源、管辖区或过滤属性。这样同一套查询可以跨地区复用。

### 3. 在线图谱查询（3 分钟）

前端请求 Spring Boot，而不是直接连接 Neo4j。后端使用参数化 Cypher：

- 多属性匹配实体；
- 精确主名称优先，避免有效成分误命中某个短登记号；
- 返回中心节点和最多 48 条直接关系；
- 节点双击或点击详情按钮可增量展开，已有节点保持原位；
- 最短路径限制在 6 跳内，避免无界遍历。

可以展示已验证路径：`Prothioconazole → 00A267-00 → Spring barley`。

### 4. GraphRAG（4 分钟）

问答不是“让大模型直接写 Cypher并执行任意查询”，而是两阶段受控流程：

1. 模型只输出最多 3 个搜索词；
2. 应用用固定参数化 Cypher 检索直接关系，并按需沿登记号扩展受限两跳关系；
3. 把“有效成分—登记号—作物或病害”等关系转成编号证据；
4. 第二次模型调用只能依据证据回答；
5. 前端把证据渲染为可点击关系。

会话层把问题、回答、识别实体和证据关系一起写入 H2。页面刷新后可以恢复完整对话；第二轮只携带最近两轮上下文以控制 token，用于解析“它”“这个登记”等指代。历史回答中的证据仍可跳回图谱重新高亮。

这样降低了任意 Cypher、幻觉和提示注入风险，也方便追踪每个结论。

### 5. 技术取舍（3 分钟）

- 选 Neo4j：在线邻域与短路径查询符合当前规模；
- 暂不选 GraphX：当前 2.2 万节点无需 Spark 集群；
- 暂不选 LangGraph：虽然已有多轮会话状态，但流程没有动态工具路由、循环核验与长任务恢复，Java 显式编排更清楚；
- 选原生 SVG 画布：当前单视图限制在 180 个节点以内，确定性环形 / 路径布局无需引入重型图形运行时；节点拖动、平移缩放和增量展开都在浏览器端完成，交互成本更可控；
- DeepSeek V4 Flash：非思考模式成本较低，适合实体规划与证据总结。

### 6. 局限与下一步（2 分钟）

不要把未完成的部分包装成已完成：

- GitHub 不含完整数据，当前缺少公开可复现的数据流水线；
- 内部节点 ID 不适合长期 API，需要业务 ID；
- 精确名称和 CAS 已使用索引，别名、拼写容错和中文名称仍需要 full-text index 或专用检索层；
- 需要增加来源、时效和地区登记状态；
- 当前已有 500 条结构回归、50 条图谱一致性问答和 30 条外部来源候选基准，但还缺少双人领域专家签字的正式金标准与生产并发压测。

## 高频面试题

### 为什么不用大模型直接生成 Cypher？

自由 Cypher 难以限定查询成本和访问范围，也更容易受提示注入影响。当前采用固定检索模板，模型只负责搜索词规划和证据总结。

### 如何减少幻觉？

答案提示明确禁止补充图谱外常识；证据有编号；前端展示关系并可跳回图谱。进一步可用规则检查回答引用编号是否存在，并建立忠实度评测。

### 最短路径会不会很慢？

接口限制 6 跳，并先用索引把起点和终点各自收敛为一个实体。在 52 条路径回归上，P50/P95 从 228.90/640.23 ms 降至 6.60/8.10 ms，路径与关系类型准确率保持 100%。该结果来自本机顺序请求，生产环境仍需按允许关系类型约束路径并补充并发压测。

### 你如何评估 GraphRAG？

评测分三层：500 条结构集核对实体 ID、标签、路径长度和关系类型；50 条语义集检查正负例、证据端点、关系约束与引用编号；30 条外部来源候选集使用 PubChem、IRAC、FRAC 和 HRAC 原子事实比较 Direct DeepSeek 与 GraphRAG。全量实验中 Direct 命中 26/30，GraphRAG 命中 30/30，但 GraphRAG 的 P50 从约 0.99 秒增加到 1.95 秒。对照评分采用确定性概念匹配，不让模型给自己打分；4 个成对差异的精确 McNemar `p=0.125`，样本量还不足以声称统计显著。当前外部集仍等待两位领域专家复核，因此只能称 provisional benchmark，不能包装成专家金标准准确率。

### Neo4j 和 GraphX 如何协作？

Neo4j 负责在线检索，GraphX 适合超大规模离线全图计算。若未来需要风险传播或社区发现，可把结果写回 Neo4j 作为节点分数或社区属性，再由在线接口查询。

### 这个项目的业务价值是什么？

把跨表、跨来源的查找转成关系路径，并让 AI 回答可以核验。它能支持登记检索、产品组合分析、植保知识查询和合规初筛，但不能替代法规与登记标签的最终判断。
