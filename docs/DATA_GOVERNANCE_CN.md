# 全球农药登记数据治理

AgriReg AI 将不同国家和地区的农药登记、有效成分、作物与病虫害数据统一到同一张关联网络中。网页以业务查询为入口，不按国家拆分站点；地区信息作为登记证据的一部分保留。

## 当前数据规模

以下结果来自 2026-08-27 对原始本地 Neo4j 快照的只读核验：

| 实体或关系 | 数量 |
| --- | ---: |
| 全部实体 | 22,328 |
| 农药登记 | 16,216 |
| 作物 | 3,112 |
| 病虫害 | 2,382 |
| 有效成分 | 318 |
| 全部关系 | 145,579 |

应用当前使用独立的清洗服务图谱：21,712 个节点、120,776 条关系，登记记录仍为 16,216 条。详细规则和差异见 [数据清洗报告](DATA_CLEANING_REPORT_CN.md)。

登记数据中可识别出 14,614 条中国登记字段集、746 条德国登记字段集、703 条欧洲成员国互认字段集，以及 153 条仍需补充来源标签的登记记录。`Member State of origin` 字段覆盖德国、意大利、波兰、罗马尼亚、英国、法国、爱尔兰等多个国家和地区。

## 统一证据模型

后续采集和导入时，每条登记记录统一补齐以下字段：

| 字段 | 含义 |
| --- | --- |
| `jurisdiction` | 登记所属国家或地区 |
| `source_name` | 数据发布机构或来源网站 |
| `source_url` | 可回查的原始登记页面 |
| `collected_at` | 采集时间 |
| `updated_at` | 来源数据更新时间 |
| `registration_status` | 统一后的登记状态 |
| `valid_from` / `valid_until` | 统一后的有效期 |
| `source_record_id` | 来源系统中的原始记录编号 |

原始字段继续保留，统一字段用于查询、比较和证据展示。这样既能兼容不同国家的登记结构，也能避免清洗过程丢失原始信息。

## 数据处理流程

1. 采集层保存原始响应、来源 URL、采集批次与文件校验值。
2. 清洗层统一国家、日期、登记状态、有效成分和作物名称。
3. 实体对齐层使用标准化名称、登记号和 CAS 号去重，并维护同义词。
4. 图谱层使用 `MERGE` 幂等导入实体和关系，同时记录来源批次。
5. 质量层检查空来源、过期登记、重复实体、乱码字段和异常翻译。
6. 发布层生成数据审计摘要，再向图谱工作台和 AI 问答提供数据。

## 当前已发现的问题

- 多来源字段直接合并在 `RegisterNumber` 节点上，字段名尚未完全统一。
- 部分记录没有原始链接、采集时间或明确地区标签。
- 153 条登记记录只有登记号和关系，需要回查来源批次。
- 存在乱码字段名和同义字段，例如多个“有效期”和“登记状态”字段。
- 有效成分描述需要通过来源页面或权威数据库做抽样复核。

这些问题不影响“全球农药登记知识图谱”的产品定位，但会影响证据导出、跨地区比较和 AI 回答可信度，因此应作为下一阶段的数据工程重点。
